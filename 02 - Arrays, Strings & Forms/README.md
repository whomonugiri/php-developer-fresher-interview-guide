# Part 2: Arrays, Strings & Forms

28 original interview topics, rewritten as a PHP 8.1+ study pack. Each numbered
file contains a short interview answer, a Hinglish explanation, a follow-up
question, and working example code. The numbering and all original topics are
preserved; the separate Q19/Q27 form entry points are preserved too.

By CODEGULLY / Monu Kumar Giri. No Composer packages, database, email delivery,
external API or JavaScript is required.

## Start here

1. Read the question and try a 30-second answer before reading the explanation.
2. Predict the example result, then run it and compare its named JSON fields.
3. Change one edge case: zero, null, a missing field, the first element or an array where a string was expected.
4. Answer the follow-up question and run the tests.

### Requirements

- PHP CLI **8.1 or newer** (the checkbox validator uses `array_is_list`). Check with `php -v`.
- PHP sessions and a writable session save path for browser exercises.
- Optional `mbstring` and `intl` for the Unicode branches in Q12. Missing extensions produce explicit `null` results and test skip notices.
- `fileinfo` for the Q26 upload exercise. If missing, that endpoint reports the requirement instead of accepting a file.
- HTTP tests use PHP streams and need `allow_url_fopen=On`; no curl or test framework is required.

### Browser forms: localhost only

Run from this directory, **with `public/` as the document root**:

```sh

```

Open [http://127.0.0.1:8002/](http://127.0.0.1:8002/). Leave this terminal running.
Use a different terminal, also in this directory, for the HTTP regression suite:

```sh
php tests/http.php http://127.0.0.1:8002
```

The built-in server is for local study only. Do not bind it to `0.0.0.0`, expose
it to the internet, or serve the repository/section root. The router and forms
check the web root, client loopback address and Host header, and refuse other
setups. Opening `.php` with `file://` or a static preview does not execute PHP.
On Windows/XAMPP you can use XAMPP's PHP executable for these same commands;
this guide does not require changing Apache's document root.

All form POSTs need the session cookie and CSRF token generated by a GET of the
form. A raw `curl -d ...` without them should return 403. DevTools can edit fields
to test server validation even when HTML `required`/`type` constraints would
normally block submission. Use fictional names, email addresses and PDFs.

## Important corrections and boundaries

- Q6, Q8, Q10, Q14 and Q15 no longer have example inputs that contradict their expected output. Q10 really subtracts ₹100 and selects prices ≥₹1000.
- Q18 explicitly uses `ENT_QUOTES | ENT_SUBSTITUTE` and UTF-8. Request values are never dumped directly into HTML. JSON examples are served with the JSON content type.
- Q21's form and handler now both use POST. Valid zero is kept and arrays are rejected.
- The Q22 example deliberately contains script-looking text; the explanation and expected escaped result now agree.
- Browser endpoints reject unsupported methods and malformed values. Validation errors use 422, CSRF errors 403, wrong methods 405 and oversized bodies 413. Unexpected infrastructure problems use 500/503.
- CSRF, shape validation and output escaping protect different boundaries. POST alone is not encryption; use HTTPS in real applications. These demos use a session-only, HttpOnly, SameSite=Strict cookie. The Secure flag is intentionally off for HTTP localhost.
- A name may contain `<` or quotes under the demo's name rules. It is still escaped on display. HTML escaping does not validate a name and is not SQL, JavaScript, URL or CSS escaping.
- `strlen` name limits are **bytes**. Phone checks are a deliberately narrow 10-ASCII-digit format, not worldwide numbering validation or proof of ownership.
- PRG prevents the usual refresh repost prompt. It does not provide transaction idempotency, deduplication or authorization.

### Q26 private upload behavior

Q26 accepts one genuine HTTP PDF upload of 1 byte through 2 MiB, checks the PHP
upload error and actual temporary-file size, detects MIME with Fileinfo, creates
a random filename, and uses `move_uploaded_file`. It ignores client filename,
client MIME and client-reported size. Saved files are in `storage/uploads/`,
outside the enforced public web root. No route lists, serves or executes them.

On POSIX, the code requests 0700 directory permissions and explicitly applies
0600 to moved files (a rename can preserve source permissions, so umask alone
is insufficient). Windows `chmod` does not implement Unix owner/group permission
semantics; use an appropriately restricted Windows account/NTFS ACL for local
study and do not infer isolation from the numeric mode. If storage or the
permission operation fails, the sample returns an error. MIME validation is not
malware detection; a PDF may still contain dangerous content.

Uploads are ignored by Git. The HTTP test uploads only a generated fictional
PDF, checks it is private, and deletes that file in `finally`. Manually uploaded
files remain until you delete them locally. Do not commit uploads or use real
resumes. Production would additionally require authentication, authorization,
CSRF defense, quotas, scanning, lifecycle cleanup, access-controlled download
handling and operational logging; these teaching endpoints are not deployable
production services.

## Interview answers and follow-up practice
### 1. Indexed, associative and multidimensional arrays

**Question:** PHP mein array kya hota hai? Indexed, associative aur multidimensional arrays mein kya difference hai?

**Short answer:** Arrays are ordered maps, not three different PHP types.

Indexed mein integer keys, associative mein meaningful string keys, aur multidimensional mein nested arrays hote hain. Access exact key se hota hai; array ka first key hamesha 0 nahi hota. PHP integer-like string keys ko integers mein convert kar sakta hai.

**Follow-up:** What happens to ["1" => "first", 1 => "second"]? One key remains: integer 1 with value "second".

### 2. Add, update, unset, count and reindex

**Question:** Array mein elements add, update, remove aur count kaise karte hain?

**Short answer:** Use [] to append, a key to update, unset() to remove, and count() to count.

unset() baaki keys reset nahi karta. count() element count hai, highest key nahi. array_values() fresh list deta hai; returned value assign karna padta hai.

**Follow-up:** Why can a three-element array have keys 1, 2, 3? Removal preserves the surviving keys.

### 3. isset, empty and array_key_exists

**Question:** isset(), empty() aur array_key_exists() mein kya difference hai?

**Short answer:** isset() excludes null; array_key_exists() includes null; empty() accepts false-like values.

Missing field aur explicit null alag business meanings rakh sakte hain. empty("0") true hai, isliye valid zero ko missing mat bolo. ?? null/missing ke liye default deta hai, zero ke liye nahi.

**Follow-up:** Which check distinguishes a missing key from a key containing null? array_key_exists().

### 4. Strict membership and array_search

**Question:** in_array() aur array_search() mein kya difference hai?

**Short answer:** in_array() returns a boolean; array_search() returns the first matching key or false.

Third argument true se value aur type dono compare hote hain. Found key 0 valid hai. Result !== false check karo; if ($key) index-zero match miss karega.

**Follow-up:** Why use strict membership for IDs? String "101" and integer 101 need not mean the same allowed input.

### 5. Push, pop, shift and unshift

**Question:** array_push(), array_pop(), array_shift() aur array_unshift() kya karte hain?

**Short answer:** push/unshift add at the end/start; pop/shift remove and return the end/start item.

push/unshift updated count return karte hain. pop/shift empty array par null dete hain. Single append ke liye [] simple hai. shift/unshift integer keys reindex karte hain; large queues mein repeated shifting costly ho sakta hai.

**Follow-up:** How would you distinguish an empty stack from a popped null item? Check the array before popping.

### 6. Merge versus union

**Question:** array_merge() aur array union operator + mein kya difference hai?

**Short answer:** array_merge() overwrites matching string keys and reindexes integer keys; + keeps left-hand keys.

Union duplicate values remove nahi karta: decision keys par hota hai. Numeric-string keys PHP array mein integer keys ho sakti hain. Defaults merge karte waqt precedence clearly decide karo.

**Follow-up:** For user options plus defaults, what does $user + $defaults do? User keys win, missing defaults are added.

### 7. Sort by value or key

**Question:** sort(), asort() aur ksort() mein kya difference hai?

**Short answer:** sort() sorts values and resets keys; asort() sorts values preserving keys; ksort() sorts keys.

Ye functions input ko mutate karte hain; result sorted array nahi hai. rsort/arsort/krsort descending versions hain. Marks ranking mein arsort() names preserve karta hai. Numeric scores ke liye SORT_NUMERIC explicit rakho.

**Follow-up:** How do you rank scores without losing names? arsort($scores, SORT_NUMERIC).

### 8. Slice versus splice

**Question:** array_slice() aur array_splice() mein kya difference hai?

**Short answer:** slice returns a portion without changing the source; splice mutates and returns removed values.

Offsets positions hain, keys nahi. slice by default integer keys reset karta hai; fourth argument true se preserve hote hain. splice numeric keys reindexes and can insert replacements.

**Follow-up:** What does array_splice($a, 1, 0, ["new"]) do? Insert at position 1 without removing items.

### 9. Unique values, keys and columns

**Question:** Duplicate values, array keys aur array columns kaise extract karte hain?

**Short answer:** unique removes repeated values; keys/values extract keys/values; column extracts one field from rows.

array_unique original keys preserve karta hai. array_values se list ban sakti hai. array_column ka third argument output keys choose karta hai; duplicate IDs overwrite earlier rows. Missing column values skip ho sakti hain.

**Follow-up:** Why avoid array_unique() as a general nested-object deduplicator? Its comparison rules are not a domain-specific identity rule.

### 10. Map, filter and reduce

**Question:** array_map(), array_filter() aur array_reduce() mein kya difference hai?

**Short answer:** map transforms, filter selects, reduce accumulates into one result.

array_filter keys preserve karta hai, isliye JSON list ke liye array_values useful hai. Callback ke bina filter 0 aur "0" bhi remove karta hai. Reduce ka initial value empty-input result aur accumulator type clear karta hai.

**Follow-up:** Which function produces a sum, and what happens for an empty list? array_reduce with initial 0 returns 0.

### 11. Concatenation

**Question:** PHP mein strings concatenate kaise karte hain?

**Short answer:** Use . to concatenate strings and .= to append.

+ arithmetic ke liye hai. Arithmetic and concatenation ek expression mein mix karte waqt parentheses lagao. Interpolation convenient hai, lekin braces variable boundary clear karte hain.

**Follow-up:** How do you append a calculated total clearly? $message .= " Total: " . ($price * $quantity);

### 12. Bytes, code points and graphemes

**Question:** strlen() aur mb_strlen() mein kya difference hai?

**Short answer:** strlen counts bytes; mb_strlen with UTF-8 counts code points.

Rupee sign 3 UTF-8 bytes hai: "₹100" = 6 bytes, 4 code points. User-perceived graphemes multiple code points ho sakte hain. mbstring optional extension hai; grapheme_strlen needs intl. File UTF-8 rakho.

**Follow-up:** Why can even mb_strlen overcount visible letters? Combining marks and emoji sequences can form one grapheme.

### 13. Trim and case conversion

**Question:** trim(), strtolower(), strtoupper() aur ucwords() kya karte hain?

**Short answer:** trim removes selected edge characters; strtolower/strtoupper/ucwords change case.

trim internal spaces collapse nahi karta aur all Unicode whitespace remove nahi karta. Results assign/use karo. ASCII examples portable hain; Unicode case conversions ke liye mbstring functions use karo. PHP 8.1 case behavior can depend on locale; PHP 8.2+ these byte functions are ASCII-only.

**Follow-up:** Does trim($name) change $name? No: assign its returned string.

### 14. Explode and implode

**Question:** explode() aur implode() mein kya difference hai?

**Short answer:** explode splits a string; implode joins array values using a separator.

explode comma ke baad spaces preserve karta hai, array_map("trim", ...) se normalize karo. Empty separator PHP 8 mein ValueError deta hai. Quoted CSV ke liye str_getcsv/fgetcsv use karo, simple explode nahi.

**Follow-up:** What does explode(",", "a,,b") produce? Three values, with an empty string in the middle.

### 15. String search and position zero

**Question:** String mein kisi word ko search kaise karte hain? strpos() mein common mistake kya hai?

**Short answer:** strpos returns the first byte offset or false; use !== false for presence.

Position 0 true match hai. strpos case-sensitive hai; stripos case-insensitive search ke liye hai. PHP 8 str_contains boolean check deta hai. Empty needle str_contains mein true hoti hai; query rules separately validate karo.

**Follow-up:** Why is if (strpos($title, "PHP")) wrong? It treats a match at offset zero as false.

### 16. Substring and replacement

**Question:** substr() aur str_replace() kya karte hain?

**Short answer:** substr extracts a byte range; str_replace replaces all matching occurrences.

Negative offset end se count karta hai. Original variable unchanged rahega unless result assign karo. Unicode character slicing ke liye mb_substr use karo; arbitrary byte cut UTF-8 tod sakta hai.

**Follow-up:** How do you learn replacement count? Pass the optional fourth argument to str_replace().

### 17. Case-sensitive and insensitive comparison

**Question:** strcmp() aur strcasecmp() mein kya difference hai?

**Short answer:** strcmp is case-sensitive; strcasecmp compares case-insensitively for ASCII text.

Equal strings par 0 return hota hai. Ordering ke liye result ka sign check karo, exact non-zero magnitude nahi; magnitude PHP versions mein change ho sakti hai. These are not natural-language collation tools.

**Follow-up:** Why is strcmp($a, $b) === 1 unreliable? Only positive/zero/negative is a stable comparison contract.

### 18. HTML escaping versus tag stripping

**Question:** htmlspecialchars() aur strip_tags() mein kya difference hai?

**Short answer:** htmlspecialchars escapes HTML output; strip_tags removes tags and is not an XSS defense.

HTML text/quoted attributes ke liye ENT_QUOTES | ENT_SUBSTITUTE with UTF-8 use karo. JavaScript, URLs, CSS aur SQL ke rules alag hain. Allowed tags with dangerous attributes still dangerous ho sakte hain. Data ko output boundary par escape karo.

**Follow-up:** Does strip_tags make arbitrary input safe inside an HTML attribute? No; quotes and context still matter.

### 19. Form action, method, name and id

**Question:** HTML form ka data PHP tak kaise pahunchta hai? action, method, name aur id ka kya role hai?

**Short answer:** action is the destination, method the HTTP verb, name the submitted key, id a DOM/label identifier.

GET displays this form; POST validates student_name. Scalar input expected hone par arrays reject karo. HTML required server-side validation replace nahi karta. Shared web bootstrap checks CSRF and request method before processing.

**Follow-up:** If an input has only id="name", what key reaches PHP? None: successful controls need a name.

### 20. GET versus POST

**Question:** GET aur POST mein kya difference hai? Kya POST automatically secure hai?

**Short answer:** GET puts form fields in the query string; POST sends form fields in the body.

GET search/filter ke liye bookmarkable hai; data-changing actions POST use karte hain. POST encrypted nahi hota: HTTPS transport encryption deta hai. Sensitive values query strings mein mat rakho; history/logs/referrers mein leak ho sakte hain.

**Follow-up:** Can a POST also have $_GET values? Yes: its URL may include a query string.

### 21. Superglobals and input types

**Question:** $_GET, $_POST aur $_REQUEST kya hain? Form input ka data type kya hota hai?

**Short answer:** $_GET and $_POST identify sources; $_REQUEST merges configured sources and hides precedence.

Form scalars normally strings, bracket fields arrays hote hain. JSON request body automatically $_POST mein decode nahi hoti. Number control trusted integer nahi hai. Validate shape and range, then strictly compare the false sentinel so 0 survives.

**Follow-up:** Why avoid $_REQUEST for a field that must be POSTed? Cookie/query precedence depends on PHP configuration.

### 22. Normalization, validation and escaping

**Question:** Validation, sanitization aur output escaping mein kya difference hai? Kya HTML validation enough hai?

**Short answer:** Normalization transforms input, validation accepts/rejects rules, escaping makes a specific output context safe.

trim helpful normalization hai, universal sanitization nahi. Invalid data ko silently repair karne ke bajaye business rule report karo. Browser validation UX hai; server authoritative hai. Store meaningful data and escape when rendering.

**Follow-up:** Can HTML escaping prevent SQL injection? No: SQL needs parameterized queries.

### 23. Email, experience and mobile validation

**Question:** Email, fresher experience aur mobile-number input validate kaise karenge?

**Short answer:** Validate email syntax, integer experience range, and the application-specific phone format separately.

0 years valid hai; filter result === false se compare karo. Phone identifier string hai, numeric quantity nahi. Demo phone rule exactly 10 ASCII digits without country code hai. Format validation ownership/deliverability prove nahi karti.

**Follow-up:** How do you establish ownership of an email or phone? A separate verified confirmation flow, not this regex.

### 24. Checkbox arrays

**Question:** Multiple checkboxes ka data PHP mein array ke form mein kaise receive karte hain?

**Short answer:** Use skills[] for multiple selected values; unchecked controls are normally absent.

Default missing skills to [], require a list of strings, limit count, then use a strict allowlist. Nested/scalar/tampered values reject karo. Deduplicate only after validation, and escape joined output.

**Follow-up:** Should an unknown value simply be dropped? This example rejects the request so bad input is visible.

### 25. Sticky forms

**Question:** Validation error ke baad form ki old values kaise retain karte hain?

**Short answer:** A sticky form re-renders submitted values after validation errors.

Normalize scalar values, collect field errors, render value/selected with HTML escaping. Password/file controls should not be prefilled with secret data. Name limit here is 200 bytes, not characters. Data is validated/displayed, not sent or persisted.

**Follow-up:** Why is escaping necessary on an error page? Malicious input is still untrusted when redisplayed.

### 26. Multipart PDF uploads

**Question:** File upload ke liye multipart/form-data aur $_FILES kyun use karte hain?

**Short answer:** multipart/form-data carries file parts; $_FILES describes uploads; move_uploaded_file moves genuine uploads.

Validate PHP upload error, shape, genuine upload, actual size and Fileinfo MIME. Never trust original filename or browser MIME. Save a random name outside public/, with restrictive permissions. PDF MIME is not malware scanning; production also needs authorization, quotas, scanning and serving controls.

**Follow-up:** Why not save user-supplied names in public/? Traversal, collisions, executable content and direct unauthorized downloads.

### 27. Post/Redirect/Get

**Question:** Form submit karne ke baad refresh par resubmission avoid kaise karte hain?

**Short answer:** Post/Redirect/Get processes POST then sends 303 to a GET result page.

header must precede output and redirect ke baad exit zaroori hai. Session flash keeps the result without exposing names in a URL. Refresh of the final GET does not repost. PRG does not stop concurrent/double-click submissions; production needs idempotency rules.

**Follow-up:** Why use 303 rather than 307? 303 changes the follow-up to GET; 307 preserves the original method.

### 28. Hidden, readonly and disabled controls

**Question:** hidden, readonly aur disabled fields mein kya difference hai? Kya inki values trust kar sakte hain?

**Short answer:** hidden and readonly values submit; disabled controls normally do not. None are trusted inputs.

Client can edit/recreate every field. Validate course against server allowlist and calculate fee from the server-owned price list; ignore posted fee/coupon. Actual purchase authorization is separate; this example only displays a demo fee.

**Follow-up:** What if the client posts fee=1 for course=php? The server still returns the configured fee of 2500.
